# 期末项目：联邦边缘智能系统

为异构边缘设备设计并实现一套完整的联邦学习系统。请构建一个能够在现实边缘约束下运行的真实或模拟联邦学习系统。

## 项目概述

期末项目要求你设计并实现一套完整的联邦学习系统，使其能够跨异构边缘设备运行。该系统应展示：当数据分散在大量设备上且无法直接集中处理时，机器学习模型如何完成训练与部署。

你的项目应整合课程中的关键内容：联邦学习、框架级优化、硬件感知设计、模型压缩、隐私保护以及完整的系统实现。

## 项目选项

### 选项 1：联邦野生动物保护

**目标：** 在相机陷阱、声学传感器和护林员设备之间训练野生动物检测模型，同时不共享原始图像、音频或敏感位置数据。

**参与者：** 相机陷阱、声学节点、护林员手机、园区网关、保护云服务器。

**挑战：** 网络连接间歇性中断、传感器依靠电池供电、不同栖息地之间的数据呈非独立同分布（non-IID）、位置数据具有敏感性。

**要求：** 动物/事件分类、分层联邦学习、安全聚合、适用于低功耗设备的模型压缩。

### 选项 2：联邦智慧农业

**目标：** 构建作物病害或作物胁迫检测系统，使各农场能够协同训练模型，同时不暴露农场图像、传感器读数或产量敏感信息。

**参与者：** 农户手机、温室摄像头、土壤传感器、农场网关、农业合作社服务器。

**挑战：** 农村地区网络连接条件有限、作物类型不同、气候条件不同、农场数据呈非独立同分布、边缘硬件资源有限。

**要求：** 作物病害或胁迫预测、设备感知调度、差分隐私、面向手机或网关的压缩模型。

### 选项 3：联邦个性化教育

**目标：** 设计一套保护隐私的学习分析系统，使学生设备能够训练模型以预测学习需求，同时不集中存储个人学习记录。

**参与者：** 学生平板电脑或笔记本电脑、教室枢纽、学校边缘服务器、地区级聚合器。

**挑战：** 学生数据敏感、设备异构、学习模式不同、公平性要求、客户端退出。

**要求：** 学生表现或投入度预测、个性化联邦学习、隐私预算管理、轻量级端侧推理。

### 选项 4：联邦家庭能源优化

**目标：** 创建一套联邦预测系统，使智能电表、恒温器、家庭中枢和社区网关能够协同学习家庭能源使用模式，同时不暴露家庭内部隐私行为。

**参与者：** 智能电表、恒温器、家庭能源中枢、社区聚合器、公用事业服务器。

**挑战：** 家庭隐私、时间序列预测、设备异构、带宽限制、异步参与。

**要求：** 能源需求预测、安全聚合、资源感知训练、适用于家庭边缘部署的压缩模型。

### 选项 5：自拟题目

如果你提出自己的联邦边缘智能应用，并且该应用具有同等的技术复杂度和现实相关性，也可以作为项目选题。

**重要：** 自拟题目必须包含异构边缘客户端、明确的联邦学习任务、隐私或安全问题、硬件感知优化以及可度量的评估指标。在提案阶段需要获得教师批准。

## 技术要求

### 核心组件——均为必需

#### 1. 联邦学习框架

- 多设备协调协议
- 客户端采样或异步参与
- 收敛情况监控与优化
- 处理非独立同分布的客户端数据

#### 2. 隐私保护系统

- 实现或模拟差分隐私
- 安全聚合协议或方案设计
- 隐私预算管理
- 威胁模型与隐私风险分析

#### 3. 硬件感知优化

- 设备能力分析
- 资源感知调度
- 动态模型分配
- 考虑计算、内存、电池和网络限制

#### 4. 模型压缩流水线

- 面向不同设备类别进行压缩
- 量化、剪枝、蒸馏或其他有充分依据的方法
- 模型大小与推理延迟分析
- 精度与效率之间的权衡评估

#### 5. 系统实现

- 完整的联邦学习系统代码
- 模拟或真实部署环境
- 性能监控与分析
- 针对客户端退出、故障或运行不稳定情况的可靠性机制

### 高级功能——选择 2–3 项

- 分层联邦学习
- 自适应系统行为
- 跨平台模型蒸馏
- 实时系统监控
- 基于区块链的参与激励机制

## 实现方式

### 真实硬件部署

- 在实际边缘设备上部署，理想情况下至少使用 3 种不同类型的设备。
- 展示来自内存、计算、电池或网络方面的真实约束。
- **成功完成真实硬件部署可获得额外加分。**

### 综合模拟

- 模拟具有不同计算、内存、电池和带宽配置的异构设备。
- 对现实网络行为建模，包括延迟、掉线和部分参与。
- 提供明确证据，说明该模拟能够反映有意义的边缘系统约束。

## 交付物

### 1. 项目提案——第 8 周截止——3–4 页

- 问题陈述与研究动机
- 所选项目选项与应用场景
- 系统架构设计
- 联邦学习方法与隐私方案
- 硬件感知设计计划
- 实现计划与评估方法

### 2. 最终实现

- 完整的联邦学习系统代码
- 部署脚本或模拟框架
- 隐私保护机制
- 模型压缩与优化流水线
- 性能监控工具
- 文档与安装配置说明
- 通过截图、照片、视频、日志、仪表盘或模拟结果进行系统演示

### 3. 最终报告——12 月 15 日截止——8–10 页

- 系统概述与架构
- 联邦学习设计与实现细节
- 隐私、安全与威胁模型分析
- 硬件感知优化与压缩结果
- 性能评估以及与基线方法的比较
- 实现分析、经验总结与未来工作

## 评分

| 组成部分 | 权重 | 关注点 |
| --- | ---: | --- |
| 系统架构 | 25% | 设计质量、可扩展性、设备异构性和现实适用性。 |
| 技术实现 | 30% | 代码质量、系统功能、联邦学习实现和创新性。 |
| 隐私与安全 | 15% | 隐私保护效果、威胁建模、安全聚合和隐私预算分析。 |
| 性能分析 | 15% | 评估质量、基准测试、系统指标、压缩分析以及有意义的结论。 |
| 系统部署 | 10% | 实际部署、贴近现实的模拟、可复现性和系统可靠性。 |
| 沟通表达 | 5% | 报告清晰度、展示质量、文档以及对设计选择的解释。 |

### 成绩等级预期

**A——90–100%：** 系统具有创新性且工程设计出色，实现复杂，隐私保护能力强，硬件感知设计考虑周全，分析深入，文档专业。

**B——80–89%：** 系统设计良好且实现扎实，隐私机制有效，性能分析充分，文档清晰。

**C——70–79%：** 满足核心要求的基础系统，能够正常运行，具有基本隐私保护能力和足够分析。

**D/F——低于 70%：** 系统不完整或存在缺陷，存在严重实现问题、隐私保护不足、评估薄弱或文档质量差。

## 建议评估指标

| 类别 | 示例指标 |
| --- | --- |
| 模型质量 | 准确率、F1 分数、AUC、MAE、RMSE、MAPE、任务特定的召回率。 |
| 联邦学习 | 收敛轮数、客户端参与率、对非独立同分布数据的鲁棒性、客户端退出容忍度。 |
| 系统性能 | 通信成本、单轮时间、推理延迟、内存占用、能耗或电池影响。 |
| 隐私与安全 | 隐私预算、隐私机制对准确率的影响、威胁分析、投毒或推断攻击模拟。 |
| 压缩 | 模型大小缩减、延迟降低、带宽节省、压缩后的精度损失。 |

## 协作政策

- **项目可根据教师要求以个人或团队形式完成。**
- 外部协作（包括与行业伙伴或其他学生合作）只有在明确注明贡献的情况下才被允许。
- 可以使用开源工具和数据集，但必须正确引用。
- 每位团队成员都必须在最终报告中清楚说明自己的个人贡献。
