# MedClaim Review

医疗理赔票据辅助审核系统

通过 AI 辅助提取医疗票据中的关键信息，帮助医疗理赔审核员在后续理赔处理前核验并纠正这些信息。

## 项目概述

医疗理赔审核员经常需要阅读提交的票据，并手工录入医院名称、服务日期和总金额等信息。这类重复工作耗时，也容易产生抄录错误。

本项目旨在通过自动提取减少手工录入，同时由人工审核员负责核验最终字段值。申请人提交理赔材料，审核员对照上传的原始文件检查提取信息。

项目目前处于提案和规划阶段。下文描述的流程与能力均为计划内容；技术选型和实现细节尚待确定。

## 用户与角色

- **申请人：**提交医疗理赔申请并附上医疗发票或账单，获得提交确认和 Claim ID。
- **医疗理赔审核员（主要用户）：**查看处理状态，对照原始文件检查提取字段，纠正错误或补录缺失值，并保存最终核验信息。

这些角色用于描述预期业务流程。账户管理和访问权限的细节将在后续设计中确定。

## 核心流程

1. 申请人提交医疗理赔申请，并附上 PDF 或图片。
2. 系统校验提交内容、存储上传文件，并记录理赔申请和文档元数据。
3. 系统创建后台处理任务，返回提交确认和 Claim ID，无需等待提取完成。
4. 后台 worker 处理文档，调用 OCR/AI 提取功能。
5. 系统保存提取字段及其置信度或结果状态，并更新处理状态。
6. 审核员对照原始文档查看提取信息。
7. 审核员确认、纠正或手工录入所需字段。
8. 系统保存最终核验值和审核记录，并与 AI 原始输出分别保留。

如果提取失败、返回无效信息或结果置信度较低，系统将明确展示问题，并允许人工核验。失败的处理任务也可以重试。提取成功后仍需人工确认。

## AI 功能

AI 的职责限定为：接收上传的医疗票据，或从票据得到的 OCR 文本，提取以下信息：

- 医院名称（`hospital_name`）
- 服务日期（`service_date`）
- 总金额（`total_amount`）
- 置信度或结果状态（如适用）

AI 辅助提取信息，由审核员核验字段值。审核完成表示提取信息已经核对，并不表示保险理赔已经获批。

## 项目范围

### 范围内

- 提交附有 PDF 或图片的理赔申请
- 持久化保存理赔元数据、文档元数据和上传文件
- 后台 OCR/AI 提取及可见的处理状态
- 保存提取结果和处理失败信息
- 文档预览，以及对提取字段的人工核验或纠正
- 保存最终核验值和审核记录
- 自动处理失败时的人工处理或重试

### 范围外

- 手写文档识别
- 欺诈检测或医疗诊断
- 自动最终理赔审批或完整的保险决策引擎
- 初始原型中的多个不相关理赔流程

具体票据模板和文档覆盖范围尚未确定。开发过程中将明确并验证初期支持范围。原型将使用合成或匿名化文档，避免在存储和日志中保留不必要的敏感信息。

## 拟议系统概览

计划中的系统包含五项主要职责：

| 部分 | 职责 |
| --- | --- |
| 提交与审核界面 | 接收理赔材料，让审核员查看文档并核验字段。 |
| 应用/API 层 | 校验请求，协调存储与任务创建，提供状态、结果和审核操作。 |
| 持久化层 | 保存理赔申请、文档元数据、处理任务、提取结果和审核记录；通过文件存储层保留文件。 |
| 后台处理 | 在提交请求之外执行提取，跟踪进度，记录完成或失败状态。 |
| OCR/AI 功能 | 将文档内容转换为供人工核验的结构化字段。 |

以上描述的是逻辑职责，并不代表已经确定具体框架、供应商或独立部署的服务。详细架构将进一步定义各部分的边界和交互方式。
