# 第 2 部分：硬件感知优化报告

## 1. 概述

本部分建立在第 1 部分 CIFAR-10 MobileNetV2 基线（测试准确率 93.71%）之上，评估四种主要优化变体：

1. 延迟优化模型。
2. 内存优化模型。
3. 带早退出分支的能耗优化模型。
4. 量化模型。

前三种是 Keras 模型，量化变体是 TFLite 模型。所有准确率均使用完整的
10,000 张 CIFAR-10 测试图片计算。测试集没有用于训练或量化校准。

## 2. 实现摘要

### 2.1 延迟优化

- MobileNetV2 宽度乘子：`alpha=0.5`。
- 输入分辨率：`160 x 160`。
- 参数量：719,034。
- 保留 MobileNetV2 的逐深度可分离卷积结构。

### 2.2 内存优化

- MobileNetV2 宽度乘子：`alpha=0.5`。
- 输入分辨率：`160 x 160`。
- 使用第 1 部分基线模型作为教师模型，进行知识蒸馏。
- 对卷积核和 Dense 核执行带掩码的幅值剪枝。
- 目标稀疏度和实际卷积核稀疏度均约为 30%。
- 使用两个带掩码的恢复训练 epoch，在微调期间持续保持零权重。

### 2.3 能耗优化

- MobileNetV2 宽度乘子：`alpha=0.5`。
- 输入分辨率：`160 x 160`。
- 在 `block_6_project` 后连接一个早退出分类器。
- 置信度至少为 0.7 的样本使用早退出分类器。
- 置信度较低的样本继续通过完整网络。
- 当前环境没有可靠的逐推理能耗计数器，因此通过延迟、早退出覆盖率和计算量减少来讨论能效，而不是使用实际焦耳测量值。

### 2.4 量化

- PTQ INT8 使用 200 张训练图片进行校准。
- QAT 在简短训练期间使用 8-bit 权重网格约束。
- 混合精度版本导出为 FP16 TFLite 模型。
- 动态范围量化在不进行校准的情况下降低权重精度。

## 3. 模型比较

基线模型和架构优化模型的延迟使用 Keras GPU 模型测量。量化模型使用单线程 TFLite CPU 解释器测量。因此，TFLite 量化模型的延迟不能直接视为相对 Keras GPU 基线的同后端硬件加速。

| 模型 | 测量后端 | 准确率 | 相对基线下降 | 参数量 | 大小（MiB） | 延迟（ms） |
|---|---|---:|---:|---:|---:|---:|
| 基线 | Keras GPU | 93.71% | 0.00 个百分点 | 2,270,794 | 26.008 | 2.497 |
| 延迟优化 | Keras GPU | 89.34% | 4.37 个百分点 | 719,034 | 8.484 | 2.456 |
| 内存优化 | Keras GPU | 84.43% | 9.28 个百分点 | 719,034 | 3.239 | 2.451 |
| 能耗优化 | Keras GPU | 87.46% | 6.25 个百分点 | 719,364 | 8.502 | 2.284 |
| PTQ INT8 | TFLite CPU | 87.84% | 5.87 个百分点 | - | 0.937 | 0.663 |
| QAT INT8 | TFLite CPU | 84.49% | 9.22 个百分点 | - | 0.937 | 0.662 |
| 混合 FP16 | TFLite CPU | 89.26% | 4.45 个百分点 | - | 1.369 | 0.535 |
| 动态范围 | TFLite CPU | 88.61% | 5.10 个百分点 | - | 0.838 | 0.973 |

## 4. 准确率保持分析

- 延迟优化模型保留了基线准确率的 95.34%，模型文件缩小了 67.38%。
- 内存优化模型保留了基线准确率的 90.10%，模型文件缩小了 87.55%。
  其 9.28 个百分点的准确率下降，是以更小的存储空间和更低的参数密度换取性能的明确权衡。
- 能耗模型的完整分支准确率为 87.74%。早退出策略准确率为 87.46%，
  并在 10,000 张样本中有 81 张使用早退出分类器，早退出比例为 0.81%。
- 混合 FP16 是准确率最高的量化版本，达到 89.26%。
- 动态范围量化生成了最小的量化模型，仅 0.838 MiB，同时保持 88.61% 的准确率。
- PTQ 的准确率与大小平衡优于简化版 QAT：准确率分别为 87.84% 和 84.49%，
  但两者的模型大小基本相同。

作业只规定第 1 部分基线的准确率应高于 85%，没有对每个优化变体规定最低准确率。因此，内存和 QAT 结果作为实际测量到的权衡如实报告，不应视为缺失了某个数值目标。

## 5. 内存管理分析

- 梯度检查点实现为仅用于训练的激活值重计算包装器。它不应被理解为会降低推理延迟。
- GPU/CPU 模型分片将特征提取和分类头分开，但引入了跨设备传输开销：
  约 3.03 ms，而未分片的延迟优化模型约为 2.46 ms。
- FP16 激活压缩应用于分类头，单张图片推理延迟约为 2.21 ms。
- Batch size 搜索测试了 1、8、16、32 和 64。Batch 64 的吞吐量最高，
  约为 9,997 images/s。

这些结果均来自开发机器上的代理测量，不是 MCU 或智能手机上的真实性能。

## 6. 推荐配置

- 通用边缘目标中准确率与大小最均衡：混合 FP16。
- 存储空间是首要限制时选择：动态范围量化。
- 校准 INT8 中综合表现最好：PTQ INT8。
- 存储空间最小的 Keras 架构：内存优化模型，但需要接受测得的准确率损失。
- 仅当应用能够接受早退出的置信度策略时使用早退出；它在当前 CIFAR-10 测试集上的覆盖率为 0.81%。
